# 企业知识库

## 目标与入口

把分散资料变成可供人检查、供文章检索、供审核追溯的企业知识。默认每品牌一个本地资料文件夹，聊天与可访问网页作为补充。先整理已有资料，再用选择卡补问关键缺口。

必读：[阶段、版本与证据约定](references/workflow-contract.md)和[知识库组织与交付格式](references/knowledge-layout.md)。涉及清洗、案例或宣传主张时，读取[内容质量原则](references/content-quality.md)。

## 接收和整理

1. 确认本次品牌、指定资料范围和现有生效知识版本。优先查找已有索引；存在同名品牌或多个知识目录时，请用户明确目标。没有资料路径时用选择卡询问入口，不扫描无关目录。
2. 为指定材料登记来源ID。记录路径或URL、原文件名、内容日期、获取日期和读取结果。使用当前可用文件工具解析正文、表格及相关图像；不把“文件已发现”写成“已完整读取”。逐文件或逐批处理，资料长时按章节继续，不静默截断。
3. 先交付资料接收清单，显示完整、部分、失败、重复及待处理项；说明哪些页、表或附件尚未覆盖。用户已明确要求连续整理本批资料时，可以继续草稿整理；否则停在接收清单，让用户检查。
4. 分别整理企业事实、行业资料、表达规则。问题集与历史文章建立独立关联索引。问题中的前提、营销口号、未经核实的旧文章不能直接升级为事实。保留重要原文信息，合并重复材料时维持来源关系。
5. 对重要企业主张建立事实条目，保留主体、内容、数值及单位、条件、地域、时间、来源位置、确认状态和公开范围。尤其注意集团与子品牌、产品系列与型号、响应与上门/修复、含税与未税、一次性与月度费用的差别。
6. 对不清楚、冲突、过期或证据不足的事项列出原始说法和依据，提出最少的关键选择卡问题。公开事实主动查证一手来源；内部价格、服务、案例和业务口径向用户确认。只更新整理稿，不改写原始材料以消除冲突。

## 确认、生效与更新

- 导入、提取和排版成功不代表事实已验证，也不代表允许公开。按批次确认公开范围，支持文件、工作表及单条事实的例外；未确认公开权限的内部材料不写入公开文章。
- 新建或更新知识库先交待确认稿、变更/冲突清单及待确认项。用户确认具体版本、事实范围和公开范围后，才形成生效版本；已有有效确认复用，不重复问。用户业务确认标为企业确认，不冒充第三方核验。
- 允许已确认、可公开且足以支撑当前文章的事实先行使用；未解决事项留在待确认区，不能混入生效事实。无需补齐全品牌或全部问题才开始单篇创作。
- 同一主张的新旧资料矛盾时，结合主体、适用范围、生效时间和证据可靠性解释差异；不能仅凭上传较晚或用户偏好覆盖相反证据。请用户澄清；争议事实暂不可用，其余已确认事实仍可使用。
- 更新时对比生效版本，列出新增、修改、失效和冲突事实；确认后另存新版本，保留旧版本和确认记录。恢复旧内容也创建新版本，并重查时间与证据有效性。
- 根据实际保存的文章—事实—来源引用关系，交付受影响的定位、简报和文章清单。只报告当前可检查的范围，不声称已查到未提供的历史内容或存在后台自动监控。
- 文章和AI生成摘要可提供候选线索，不作为证明自身主张的独立依据；新增可复用事实仍须回到原始材料并经确认入库。

## 本阶段产出与交接

按知识库组织参考交付接收清单、来源索引、待确认知识稿、缺口/冲突表、公开范围记录。获确认后交付生效知识版本、事实索引和变更影响清单。

聊天给出读取覆盖、确认范围、关键缺口及绝对文件链接。默认阶段交付后停下；提供“继续品牌定位”或“按问题集选题”的接续建议，不自动生成定位和文章。没有指定目录时依共享约定放在当前任务输出目录，不将某个品牌资料写入本技能安装目录。
